# 주행·노면 분석 로그

## 실행

```bash
roslaunch unita_launch test_map_raceline.launch morai_ip:=127.0.0.1 log:=true
```

이 명령으로 주행과 기록이 함께 시작됩니다. 화면도 확인하려면 별도 터미널에서 실행합니다.

```bash
roslaunch unita_waypoint map_debug.launch
```

매 실행마다 `/home/unita/unita_ws/src/unita_waypoint/log/driving_run_*/`에 새 폴더를 만듭니다.
터미널의 `Driving log session (log=true)`에 정확한 경로가 나옵니다.
디버그 화면 없이 실행해도 제거한 노면·장애물 후보 점을 기록합니다.

## 저장 내용

| 파일 | 분석할 내용 |
| --- | --- |
| `sensors_*.bag` | 원본 `/lidar3D`, `/imu`, `/gps`, 계산한 차량 위치, 노면·장애물 점, 장애물 추적, 경로, 목표·현재 속도, 제어 명령, ROS 오류 |
| `events.jsonl` | 노면 보정 상태, IMU 거절·시각 차이, 차선 선택·변경 이유, 정지 이유, 속도 제한별 값, 실제 액셀·브레이크·조향, 제어 송신 상태 |
| `raceline_*.jsonl` | 차선 선택 및 주행·정지 이벤트 요약 |
| `rosparams.yaml`, `lidar_params.yaml` | 마지막 수집 시점의 전체 ROS 설정과 라이다 설정 |
| `events.jsonl`의 `parameters` | 설정 변경 이력: 2초마다 확인하고 값이 달라지면 저장 |
| `config/` | 시작 시 사용한 경로, 노면 필터, 지도 보정, 속도 계획, 센서·제어·위치 계산 설정 |
| `code/` | 분석에 필요한 주행·라이다·제어·센서 수신·위치 계산 코드 사본 |
| `manifest.json` | 시작·종료 시각, 파일 목록·해시, 수신 횟수, 아직 없는 토픽 |
| `rosbag_record.log` | bag 기록기의 시작·종료 및 오류 |

bag은 LZ4로 압축하고 512 MB마다 분할합니다. 용량은 라이다 점 수와 실행 시간에 따라 달라집니다.
JSONL에는 점군을 중복 저장하지 않습니다. 토픽 이름이 다르거나 센서가 연결되지 않으면 해당 데이터는
기록할 수 없으며 `missing_topics`와 수신 상태에 남깁니다.

`log:=true`에서만 시뮬레이터의 실제 차량 위치와 전체 Ego UDP 패킷을 별도 진단 토픽에 기록합니다.
IMU·GPS 원본 UDP도 기록하므로 센서 원래 시각과 ROS 수신 시각을 비교할 수 있습니다.
실제 제어 UDP 송신 바이트와 송신 사유도 기록하여, 주행 노드의 명령과 통신 감시기의 제동을 구분합니다.
이 진단 토픽은 주행·노면 필터의 입력으로 사용하지 않습니다.
`log:=false`에서는 이 기록기와 추가 진단 토픽을 생성하지 않으며 실제 차량 위치 필드를 읽지 않습니다.
기존 Ego 수신기의 전체 패킷 형식은 아직 Competition Vehicle Status 형식으로 교체되지 않았습니다.

## 기록할 상황

1. 장애물 없는 평지에서 정지 상태를 5초 정도 기록합니다.
2. 가속 후 급정지하고, 멈춘 뒤 5초 정도 더 기록합니다. 가능하면 2~3회 반복합니다.
3. 실제 정적 장애물 앞에서도 같은 동작을 기록합니다. 가능하면 움직이는 차량과 경사로도 추가합니다.
4. 문제가 생긴 대략적인 시각, 위치 또는 경로 구간을 메모합니다. 영상이 있으면 로그 시각과 맞춰 주세요.
5. Ctrl-C로 주행 launch를 정상 종료하고 bag 저장이 끝날 때까지 기다립니다.

종료한 폴더 경로를 알려주면 그 안의 자료를 함께 분석할 수 있습니다. 분할된 bag도 모두 남겨 주세요.
MORAI 센서 설정 화면의 라이다·IMU 위치와 회전값은 ROS에서 자동으로 읽을 수 없으므로,
화면 캡처도 함께 있으면 장착 보정 오류를 확인하는 데 도움이 됩니다.

## 초록 점이 없을 때

초록색은 노면으로 **확인되어 제거한 점**입니다. 왼쪽 상태가 다음 중 무엇인지 확인합니다.

- 라이다 점군 수신 대기 / 차선 정보 대기 / 차량 위치 대기
- 라이다 좌표계 오류 / 라이다 시각 불일치
- IMU 누락·지연: 기존 높이 판정만 수행
- 노면 미확인: IMU는 있지만 노면 평면을 아직 확정하지 못함
- 노면 확인: 평면 수와 제거한 점 수 표시

지도 아래에 숨는 문제를 피하도록 표시용 초록 점만 지도 위 높이로 옮겼습니다.
물리적인 높이와 필터 결과는 원본 토픽과 bag에 그대로 남깁니다.

## IMU 보간과 기존 높이 조건

라이다 측정 시각의 앞뒤 **IMU 자세**를 보간합니다. GPS 위치를 자세 보간에 사용하지 않습니다.
현재 UDP 브리지는 기본적으로 수신 시각을 ROS 헤더에 넣으므로, 50 ms 제한은 헤더의 시각 차이이며
실제 센서 지연을 보장하는 값은 아닙니다. 원본 UDP와 헤더를 함께 분석해 확인해야 합니다.

`0.22 < z < 2.6 m`는 센서 장착 변환 후 차량의 기준 노면을 z=0으로 둔 점 높이 조건입니다.
IMU가 없거나 해당 구간의 노면을 확인하지 못했을 때 사용하는 기존 판정입니다.
왼쪽 기존 파라미터 표에서 `obstacle_min_height_m`(기본 0.22)과
`obstacle_max_height_m`(기본 2.6)을 입력 후 Enter 또는 적용으로 바로 바꿀 수 있습니다.
하한은 0 이상이고 상한보다 작아야 합니다. 잘못된 범위는 기존 값을 유지하며 오류를 표시합니다.
노면이 확인된 구간에서는 평면과의 거리(기본 0.04 m)로 노면을 제거하며, 10 cm 일괄 제거 필터는 없습니다.
확인된 노면에서는 높이 하한 대신 이 평면 허용오차를 사용하고, 높이 상한은 평면 기준 높이에 적용합니다.

노면 분석기는 한 번 실행할 때 고정 설정을 사용합니다. 기록 도중 파라미터를 바꿨다면
`parameters` 이력과 적용 확인 토픽을 기준으로 구간을 나눠 분석해야 합니다.

## 2026-10-13 주행 안정화

제공된 MORAI 센서 설정은 `config/morai_sensor_settings.json`에 보관하며 새 기록의 설정 사본에 포함합니다.
LiDAR 위치 (1.4, 0, 1.23 m), LiDAR·IMU 장착 회전 0°는 기존 변환과 일치합니다.
같은 기록에서 측정한 노면 높이에 맞춰 별도 `ground_reference_z_m=-0.38`을 적용합니다.
장착 높이를 바꾸는 값이 아니며 다른 센서·차량 설정에서는 재보정이 필요합니다.

왼쪽 기존 파라미터 표에 다음 항목도 표시·실시간 적용됩니다.

| 파라미터 | 초기값 | 동작 |
| --- | --- | --- |
| `ground_reference_z_m` | -0.38 m | 근거리 평면 높이 기준; 미확인 구간의 높이 하한·상한도 이 기준에 대한 높이 |
| `track_confirm_time_s` | 0.2 s | 최소 3회와 지속 시간으로 추적 확인 |
| `avoidance_emergency_ttc_s` | 1.0 s | 차선 변경 중 가까운 충돌 예상 시 즉시 완전 제동 |
| `avoidance_brake_limit` | 0.35 | 먼 차선 변경 충돌 예상에 의한 일반 감속의 페달 상한 |
| `avoidance_clear_hold_s` | 0.4 s | 정지 해제 전 안전 판단 유지 시간; 새 점군 3회도 필요 |
| `restart_accel_rate_per_s` | 0.5 /s | 액셀 증가량 제한, 완전 제동과 액셀 해제는 즉시 |

작은 미확인 물체는 멀리 있을 때 확인 전 차선 변경 근거에서 제외합니다.
차량의 반응·정지거리 안에 있는 물체와 큰 물체는 처음 관측부터 보호 대상으로 유지합니다.
추적 크기가 크게 변하면 새 물체로 시작하고, 속도 관측이 불안정하면 먼 미래로 외삽하지 않습니다.
속도 신뢰도가 부족한 뒤차는 차선 변경을 계속 막습니다.

진행 중 차선 변경에서 `transition_slowing`은 예상 충돌 지점까지 멈출 수 있는 속도 상한을 계산합니다.
충돌까지 1초 이하, 접촉까지 주행거리 1 m 이하, 또는 반응·정지거리가 부족하면
`transition_emergency`로 즉시 완전 제동합니다. 센서 누락·경로 소실에 의한 제동도 유지합니다.
일반 감속의 브레이크 0.35는 물리적인 감속도 3 m/s²를 보장하는 값이 아니며 차량 반응을 재기록해 검증해야 합니다.

정지 이후 목표 속도가 다시 양수가 되어도 0.4초와 서로 다른 새 점군 3회가 확인되기 전에는 제동을 유지합니다.
이때 `clearance_confirmation`으로 기록하며 실제 적용 목표는 0, 요청 목표는 별도 필드에 남깁니다.
새 위험 판단은 확인을 즉시 초기화합니다. 액셀은 매초 0.5 이하로 증가하고 브레이크와 동시에 출력하지 않습니다.

기존 기록에서 전체 ROS 파라미터 사본이 비어 있던 문제는 로컬 캐시 대신 master의 실제 설정을 읽도록 수정했습니다.
실시간 파라미터 조회도 같은 방식으로 바꿔 다른 프로세스에서 수정한 값이 주행 노드에 반영되도록 했습니다.
원본 로그는 보존합니다. 이번 수정의 검증 자료는 해당 기록의 `analysis/stability/`에 저장합니다.
